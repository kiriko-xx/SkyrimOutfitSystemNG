1.5.41: fix the start-up crash (recursive golden store lock + exception guards)

The golden items store was locked with a plain std::mutex while Golden::ImportText()
locked it again through the public TotalCount(), so MSVC raised
std::system_error("resource deadlock would occur") on the same thread and nothing
caught it inside the SKSE message handler: the game closed on every start once
OutfitSystemGoldenItems.json existed (written by the 1.5.39 crash session).

- g_mutex is a std::recursive_mutex now, and locked code paths use TotalCountLocked()
- the kDataLoaded golden load is wrapped in try/catch (fallback: empty golden list)
- MessageHandler is a try/catch shell around HandleMessage()
- tests/golden_lock_guards.ps1 guards all of the above

Engine side untouched: hooks, attachment, slot cleanup, .tri targets, scene outfits,
slot policies, ESP outfits and the golden page keep their 1.5.40 behaviour.
